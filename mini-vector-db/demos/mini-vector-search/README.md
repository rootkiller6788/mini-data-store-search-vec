## 概述

向量搜索 (Vector Search) 是现代 AI 应用的基础设施之一。
它将非结构化数据 (文本、图像、音频) 转换为高维向量，
通过近似最近邻 (ANN) 搜索快速找到语义相似的项。

### 核心价值

- **语义理解**: 不仅匹配关键词，更理解语义含义
- **多模态**: 文本、图像、音频统一为向量空间
- **高效检索**: 十亿级数据毫秒级响应
- **可扩展**: 水平扩展支持 PB 级数据

## 第二阶段: 向量预处理

### L2 归一化

```
v_normalized = v / ||v||₂

作用:
- 余弦相似度 ↔ 欧氏距离等价
- 数值稳定性
- 提高 ANN 索引质量
```

### 降维 (PCA / Random Projection)

```
高维 (1024d) → PCA → 低维 (128d)

好处:
- 减少内存占用
- 加速距离计算
- 去除冗余/噪声维度
```

### 中心化 (Centering)

```
v' = v - mean(V_dataset)

适用于使用内积相似度的场景
```

## 第三阶段: 索引构建 (Indexing)

### 索引选择决策树

```
      数据量 N
         │
    ┌────┴────┐
    │         │
  N<10K    N≥10K
    │         │
 BF/Flat  内存限制?
    │      ┌──┴──┐
    │   严格   宽松
    │      │      │
    │   IVF-PQ  HNSW
    │   (压缩)  (高性能)
    │
```

### 离线索引构建流程

```c
// 伪代码
void build_index(Vector *dataset, int n) {
    // 1. 选择索引类型
    IndexType type = select_index(n, memory_budget);

    // 2. 训练 (如需要)
    if (type == IVF || type == IVF_PQ) {
        train_kmeans(dataset, n);
        train_pq_codebook(dataset, n);
    }

    // 3. 插入所有向量
    for (int i = 0; i < n; i++) {
        index_add(&index, &dataset[i], i);
    }

    // 4. 持久化到磁盘
    index_save(&index, "index.bin");
}
```

### 增量更新

| 方法 | 描述 | 适用 |
|------|------|------|
| 直接插入 | 新向量插入已有索引 | HNSW, IVF |
| 分段索引 | 新数据建新索引，查询合并 | 所有 |
| 重训练 | 定期重建整个索引 | IVF-PQ |

## 第四阶段: ANN 检索

### 单次查询流程

```
query_vector → preprocess → index.search(k) → candidate_ids[]

详细步骤:
1. 查询向量预处理 (归一化)
2. 索引路由 (选择搜索范围):
   - HNSW: 从 entry_point 多层贪婪下降
   - IVF: 选择 nprobe 个最近聚类中心
   - LSH: 计算所有哈希表的桶ID
3. 候选生成 (Candidate Generation):
   - 扫描相关区域的向量
   - 用近似距离 (PQ/量化) 快速评分
4. 候选排序:
   - 维护大小为 k 的最大堆
   - 返回 top-k 结果
```

### 批量查询优化

```
batch_size = 32-256

优化技术:
- 向量化计算 (SIMD)
- 提前物化 (Early Materialization)
- 流水线并行 (查询处理与 IO 重叠)
- GPU 批量推理
```

## 第五阶段: 后处理与重排序 (Rerank)

### Rerank 策略

```
候选集 (100-1000 个)
      │
      ↓
  粗排 (近似距离)
      │
      ↓
  精排 (精确距离)   ←── 只对 top-N 候选
      │
      ↓
  过滤 (标量条件)
      │
      ↓
  top-k 结果
```

### 标量过滤

```sql
-- 混合查询示例
SELECT * FROM vectors
WHERE
    category = '电子产品'
    AND price BETWEEN 100 AND 500
    AND rating >= 4.0
ORDER BY vector_distance(query_embedding) ASC
LIMIT 10;
```

### 融合排序

```
final_score = α × vector_similarity + β × text_relevance + γ × popularity
```

## RAG (检索增强生成)

### RAG 架构

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  User Query  │────→│  Embedding   │────→│ Vector DB   │
│  "What is.." │     │  Model       │     │  Search     │
└─────────────┘     └─────────────┘     └──────┬──────┘
                                                 │
                                          top-k docs
                                                 │
                                                 ↓
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   Answer     │←────│    LLM       │←────│  Prompt     │
│   "Based on" │     │  Generation  │     │  + Context  │
└─────────────┘     └─────────────┘     └─────────────┘
```

### RAG 中的向量搜索要点

1. **分块策略 (Chunking)**:
   - 固定大小: 512 tokens (简单)
   - 语义分块: 基于句子/段落 (更好)
   - 重叠窗口: 256 tokens overlap (防止信息断裂)

2. **元数据管理**:
   ```
   每个 chunk 存储:
   - 向量 (768d)
   - 文本内容
   - 文档 ID, 页码, 章节
   - 时间戳, 来源 URL
   ```

3. **混合检索 (Hybrid Search)**:
   ```
   rank = α × vector_score + (1-α) × bm25_score

   结合向量语义搜索与关键词匹配的优势
   ```

4. **Rerank 模型**:
   ```
   top 100 (ANN) → Reranker (BGE-Reranker) → top 5 → LLM
   ```

## 推荐系统

### 双塔模型 (Two-Tower)

```
              ┌──────────────┐
  User ──────→│ User Tower   │────→ user_embedding (128d)
  Features    └──────────────┘
                                         │
                                   dot product
                                         │
              ┌──────────────┐           │
  Item ──────→│ Item Tower   │────→ item_embedding (128d)
  Features    └──────────────┘

  score(user, item) = user_emb · item_emb
```

### ANN 在推荐中的角色

```
召回阶段 (Recall):
  百万级物品 → ANN (IVF-PQ) → 千级候选
    ↓
粗排阶段 (Pre-ranking):
  千级 → 轻量模型 → 百级
    ↓
精排阶段 (Ranking):
  百级 → 深度模型 → 十级
    ↓
重排阶段 (Re-ranking):
  十级 → 多样性调整 → 最终展示列表
```

```

  "苹果手机" → 精确匹配 "苹果" AND "手机"
```

## 性能优化指南

### 索引层优化

| 技术 | 效果 | 代价 |
|------|------|------|
| SIMD 加速距离计算 | 2-8x 加速 | 代码复杂度 |
| 量化 (PQ/SQ) | 4-32x 内存压缩 | 召回降低 1-5% |
| 预取 (Prefetch) | 10-30% 加速 | 平台相关 |
| 图压缩 (edge compression) | 2x 内存减少 | 略降召回 |
| GPU 加速 (FAISS) | 10-50x 加速 | GPU 成本 |

### 系统层优化

```
1. 连接池: 复用数据库连接
2. 缓存: Redis 缓存热门查询结果
3. 分片: 按 ID 哈希分布到多个节点
4. 副本: 读多写少场景增加只读副本
5. 异步: 写入异步化，查询同步
6. 预加载: 索引 mmap 到内存
```

### 查询优化清单

```
□ 查询向量是否做了 L2 归一化?
□ ef/efSearch 是否根据召回要求调优?
□ nprobe 是否平衡了延迟与召回?
□ 是否添加了合理的标量过滤?
□ 批量查询是否合并了同一聚类?
□ 结果缓存是否命中?
```
